# Sunrise Drawing Editor | 도면 편집기

온맵 PDF, DXF, DWG(ODA File Converter 또는 DWGSUPPORT 지원 LibreCAD 별도 설치 필요)를 여러 개 열어 레이어를 켜고 끄며 확인하고, 선택한 도면의 현재 레이어 상태를 **PNG/JPG 이미지**로 저장하는 Windows 데스크톱 프로그램입니다. 한 도면에서 만든 레이어 ON/OFF 규칙을 저장해 여러 온맵 도엽에 일괄 적용하고, 선택한 파일을 한 번에 개별 이미지로 추출할 수 있습니다. 버전 번호·자동 업데이터 없이 단일 소스 제품으로 운영합니다.

## Windows onefile + Sunrise Group 서명 빌드

- Windows 10/11 x64, **현재 설치된 Python 3.11 이상(3.12 지원)** 환경에서 **`BUILD_ONEFILE.cmd`** 를 실행합니다. CMD만 사용하며 PowerShell 및 가상환경은 사용하지 않습니다.
- 단일 EXE 생성 위치: **`dist\Sunrise Drawing Editor.exe`**. 기존 Python의 종속성이 충족되면 pip 설치를 생략하며 Qt WebEngine 등의 미사용 패키지를 받지 않도록 `PySide6-Essentials`만 요구합니다. PyInstaller는 Windows에서 빌드해야 Windows EXE를 생성합니다.
- 빌드 순서: Python 64비트/버전 확인 → 누락 의존성만 설치 → 소스 검사 → onefile 임시 패키징 → 패키지 실제 기동 검사(`--self-test`) → Sunrise Group 코드서명 및 내장 인증서 확인 → 서명 후 기동 검사 → SHA-256 확인 후 게시. **서명 실패 시 이전 배포 EXE를 덮어쓰지 않습니다.**
- Windows `CurrentUser\My`의 유효한 `CN=Sunrise Group` 서명 인증서가 있으면 **재사용**하고, 없으면 `certutil`로 **로컬 자체서명 테스트 인증서**를 한 번 가져옵니다. Windows SDK `signtool.exe`가 설치돼 있어야 합니다. 빌드할 때마다 임의로 새 게시자 ID를 만들지 않습니다.
- 실제 공인/사내 PKI PFX가 있는 경우 `SUNRISE_SIGN_PFX_PATH`와 `SUNRISE_SIGN_PFX_PASSWORD` 환경변수로 지정합니다. 비밀키, PFX, 비밀번호는 ZIP이나 소스에 포함하지 않습니다. 선택적 타임스탬프 서버는 `SUNRISE_TIMESTAMP_URL`로 설정합니다.
- **주의:** 자동 생성되는 자체서명은 Authenticode 서명 자체는 생성하지만, 공인 인증기관의 신뢰를 받는다는 뜻이 아닙니다. Windows SmartScreen 및 게시자 검증 경고가 발생할 수 있으며 공식 대외 배포용 신뢰 서명 대체품이 아닙니다.
- `dist\SHA256.txt`와 `dist\SIGNATURE_STATUS.json`이 생성됩니다. 공지사항·업데이트 기능, 네트워크 서비스, 별도 설치 프로그램은 만들지 않습니다.
- PyInstaller onefile은 시작 시 자체 임시 경로에 Python/Qt DLL을 풀고 실행합니다. EXE 하나로 배포하지만 **완전한 무압축 단일 파일 메모리 실행 방식은 아닙니다.**
- **라이선스 확인 필수:** 현재 PDF 렌더러 `PyMuPDF`는 AGPLv3/상용 이중 라이선스입니다. 독점·비공개 바이너리의 외부 배포는 상용 라이선스 검토 또는 AGPL 준수가 필요합니다. `PySide6` 및 다른 의존성의 재배포 의무도 확인하십시오.

## 이전 개선: CAD ON/OFF 반복 렌더링

- 작은·중간 규모의 CAD에서는 `ezdxf` 그리기 명령을 1회 기록한 뒤 레이어 상태 변경 시 **기록한 명령을 레이어 필터로 재생**합니다. 원래 CAD 객체 그리기 순서를 보존하고, 개별 레이어 이미지를 억지로 합치지 않습니다.
- 이 캐시는 파일 160MiB, modelspace 객체 45,000개, 그리기 명령 55,000개 조건을 만족할 때만 시도합니다. 조건에 맞지 않으면 기존 CAD 렌더러를 그대로 사용하므로 파일 자체를 거부하지 않습니다.
- 합성 DXF 20,000개 객체 3회 측정 중앙값에서 레이어 변경 미리보기 2.5009초 → 1.9211초를 확인했습니다. 실제 100MB 이상 DXF/DWG는 미검증입니다.
- 상세 측정, 메모리 보호 조건, 신규 회귀시험은 `CAD_RENDER_OPTIMIZATION.md`에 기록했습니다.

## 최신 개선: CAD 레이어를 PDF OCG로 한 번만 생성

- 미리보기에서 CAD 객체를 매번 PDF로 재작성하지 않도록, 크기 조건을 충족한 도면은 최초 1회 **내부 OCG 레이어가 있는 PDF**를 생성합니다.
- 변경하는 레이어가 전체 도면 경계에 영향을 주지 않으면 PyMuPDF의 OCG ON/OFF로 바로 반영합니다. 확대 클립 미리보기와 PNG/JPG 추출도 해당 상태를 사용합니다.
- 경계 레이어를 끄거나 켜 도면 크기·종횡비가 바뀌는 경우, 잘림/왜곡을 막기 위해 자동으로 기존 전체 CAD 레이아웃 렌더링 경로로 돌아갑니다.
- 합성 20,000 객체 DXF(2.42MB)의 레이어 변경 중앙값은 **1.171초 → 0.064초**로 감소했습니다. 최초 화면 생성은 **2.483초 → 2.637초**로 소폭 늘었습니다.
- 기존 회귀 46개와 신규 5개를 합쳐 **51/51 PASS**입니다. Windows 실물 및 100MB 이상 CAD 실물은 미검증입니다.
- 상세 내용 및 검증값은 `CAD_NATIVE_LAYER_OPTIMIZATION.md`를 참조하십시오.

## 추가 최적화: DXF 카탈로그 및 공간 선별 미리보기

- **대량 파일 등록:** 일반 ASCII DXF는 최대 16MiB의 헤더/테이블 영역을 읽어 LAYER 이름과 기본 ON/OFF만 추출합니다. 대형 도면마다 모델 전체를 미리 여는 중복 작업을 피합니다. 지원하지 않는 구조/인코딩은 기존 전체 파서로 복귀합니다.
- **대용량 확대:** PDF 중간 도면이 캐시에 보존되지 않는 대형 CAD에 한해 단순 선/원/호 등 위치가 확실한 객체를 32×32 공간 인덱스로 선별합니다. INSERT/해치/문자/XREF 등은 항상 기존 도면 렌더러로 전달합니다.
- **속도 선택:** 메모리에 PDF 중간 렌더가 남아 있다면 기존 PyMuPDF 클립이 더 빠르므로 공간 인덱스를 실행하지 않습니다. 색상·레이어 조합/도면 경계를 임의로 바꾸지 않습니다.
- **스레드:** 확대·미리보기를 같은 작업자에서 수행해 스레드별 CAD 전체 재파싱을 줄이고, 일괄 추출은 별도의 작업자로 분리합니다.
- 합성 DXF 24,000개 객체의 PDF 미캐시 확대 1회에서 2.732초 → 0.193초를 실측했고, 비교한 확대 4개 상태에서 픽셀 동일성을 확인했습니다. 최초 도면 읽기·전체 렌더링 시간까지 개선됐다는 뜻은 아닙니다.
- 구체적인 적용 조건·한계·재현 시험은 `LARGE_CAD_OPTIMIZATION.md`에 있습니다. 실제 100~500MB CAD 실기 및 Windows PySide6·서명은 **NOT RUN**입니다.

## 수백 MB 도면 최적화 동작

- 수십~수백 개 파일을 한꺼번에 선택하면 **경로부터 즉시 목록에 등록**하고 레이어 메타데이터는 전용 단일 작업 큐에서 차례로 읽습니다. 아직 읽지 않은 파일은 `(읽는 중)`으로 표시하고, 읽기 완료 전 규칙 적용·추출을 막아 잘못된 결과를 방지합니다.
- UI에는 각 파일의 **레이어명/표시상태/페이지 수만 유지**합니다. 수백 MB CAD 전체 객체를 여러 개의 GUI 문서 객체로 보존하지 않습니다.
- 미리보기·이미지 추출 작업은 스레드별 1개 문서만 재사용하며 기존의 화면 영역 재렌더링, PDF OCG 상태 변경, 대용량 타일 출력 기능을 그대로 유지합니다.
- DXF는 MIT 오픈소스 `ezdxf` 렌더러를 그대로 사용하되, CAD의 과거 레이어 조합을 **최대 3개/총 96MB (조합당 64MB 이하)** 재사용하도록 개선했습니다. 자주 같은 레이어 조합을 켜고 끄는 경우 렌더링 반복을 줄입니다.
- DWG는 먼저 ODA 변환기 사용을 시도하고, ODA가 없으면 별도 설치한 LibreCAD CLI `dwg2dxf`를 시도합니다. LibreCAD가 `DWGSUPPORT` 없이 빌드됐다면 해당 기능은 동작하지 않습니다. LibreCAD 실행파일은 onefile EXE에 포함하지 않습니다.
- DWG 변환기 실행 위치를 직접 지정하려면 `SUNRISE_LIBRECAD_EXE` 환경변수를 사용합니다. 변환 중 임시 DXF는 작업 완료 후 정리하며 원본을 덮어쓰지 않습니다.
- ezdxf의 `iterdxf`는 초대형 ASCII DXF의 **객체 스트리밍** 기능이 있지만 복잡한 INSERT/블록/스타일을 전부 보존한 즉시 렌더링과는 다른 역할이라 이번 버전의 일반 렌더링에 강제로 적용하지 않았습니다.
- 파일 크기만으로 처리속도·메모리 상한을 보장할 수 없습니다. 실제 수백 MB 도면의 블록, 해치, 폰트, XREF 및 출력 해상도 규모에 따라 처리시간이 달라집니다.

## 공개 소스 검토 및 라이선스

자세한 비교와 소스 링크는 `OPEN_SOURCE_REVIEW.md`를 참조하십시오. GPL 라이선스 코드인 LibreCAD/LibreDWG를 EXE에 무단으로 복사하거나 정적 링크하지 않았습니다.

## 실행

1. Windows Python 3.11 이상(3.12 지원)에서 `INSTALL_AND_RUN.cmd`를 실행합니다. 기존 설치된 Python에 필요한 런타임 패키지만 설치하며 가상환경을 생성하지 않습니다.
2. 두 번째 실행부터 `RUN.cmd`를 사용합니다.
3. DWG는 별도 **ODA File Converter** 또는 **DWGSUPPORT 지원 LibreCAD**가 필요합니다. PDF/DXF는 변환기 없이 사용 가능합니다.
4. 이 ZIP은 **Windows onefile EXE를 빌드할 수 있는 소스**입니다. 실제 서명된 EXE는 Windows에서 `BUILD_ONEFILE.cmd`를 실행해야 생성됩니다. **CMD 진입점만 제공하며 .ps1/.venv는 사용하지 않습니다.**

필요 라이브러리: `PySide6-Essentials`, `PyMuPDF`, `ezdxf`, `Pillow` (패키징된 `requirements.txt` 참조).

## 사용 — 여러 온맵 PDF 일괄 처리

1. **도면 추가**로 온맵 PDF 여러 장(또는 DXF, DWG)을 한꺼번에 엽니다.
2. 첫 번째 온맵을 선택하고 가운데 레이어 체크박스에서 원하는 레이어만 켭니다. **규칙 저장** → 이름(예: `온맵 작업용`)을 입력하면 현재 레이어 ON/OFF가 저장됩니다.
3. 왼쪽 파일 목록에서 `Ctrl`(개별), `Shift`(연속), **전체 선택** 버튼으로 일괄 적용할 도면을 선택합니다. 레이어 패널의 저장된 규칙을 선택한 후 **선택 도면 적용**을 누릅니다. 일치한 도면 수, 변경 수, 없는/중복/잠긴 레이어 수를 알려줍니다.
4. 앞으로 추가하는 동일 형식 도면에도 같은 규칙을 바로 적용하려면, 저장된 규칙을 먼저 선택한 후 **신규 도면 추가 시 선택 규칙 자동 적용**에 체크합니다. 초기 기본값은 **꺼짐**입니다.
5. 추출할 도면들을 왼쪽 목록에서 다중 선택하고, 하단에서 **PNG 또는 JPG**, 저장 폴더를 지정합니다. **선택 도면 추출**을 누르고 확인합니다. 선택한 도면마다 **각각 하나의 이미지 파일**을 순차 생성합니다.
6. 우측 미리보기는 현재 포커스가 있는 도면 한 개를 보여줍니다. 레이어 체크박스 편집, 휠 확대/드래그 이동, 현재 페이지 이동은 기존과 동일합니다.

### 레이어 규칙이 적용되는 방식

- 내부 PDF OCG 번호는 도면마다 다를 수 있으므로 **레이어 이름 기준으로 적용**합니다. Windows/유니코드 표기 차이(NFKC, 대소문자)는 정규화하되, 이름이 의미 있게 다른 레이어를 임의로 추론해 변환하지 않습니다.
- PDF 규칙은 PDF에, DXF 규칙은 DXF에, DWG 규칙은 DWG에만 적용합니다. 다른 형식의 도면은 자동 건너뛰며 결과에 표시합니다.
- 존재하지 않는 레이어는 현행 상태를 그대로 둡니다. 같은 이름이 중복된 레이어나 잠긴 레이어도 임의로 변경하지 않습니다. 적용 가능한 레이어를 한 번에 업데이트하여 불필요한 렌더링을 방지합니다.
- 규칙은 Windows 사용자별 앱 데이터 위치의 `layer_rules.json`에 저장됩니다. 프로그램 소스 ZIP 교체와 별도로 유지되며 **원본 도면 파일에는 기록되지 않습니다.** 규칙 교체·삭제 시 확인 절차가 있습니다.
- 왼쪽 목록에서 아무 파일도 선택하지 않았다면 일괄 적용 및 추출이 실행되지 않습니다. 선택한 파일의 **현재 페이지 1장**씩 출력합니다(다중 페이지 PDF 전체 페이지 자동 추출은 별도 기능입니다).

### 일괄 출력·안전 정책

- 출력 이름은 `원본파일명_레이어적용.png`(또는 `.jpg`)이며 중복이면 `_2`, `_3` 등을 붙입니다. **기존 파일을 덮어쓰지 않습니다.** 도면명이 같아도 각각 저장됩니다.
- 추출 버튼을 누른 시점의 레이어 상태와 페이지를 **파일별로 스냅샷**으로 고정합니다. 작업 중 다른 파일을 열거나 미리보기 레이어를 바꿔도 실행 중 배치에 영향을 주지 않습니다.
- 일괄 처리 중에는 전체 진행률과 현재 처리 파일을 보여줍니다. 버튼을 다시 누르면 취소를 요청합니다. 이미 정상 완료된 파일은 남고, 취소 중이던 파일의 불완전 출력은 제거합니다.
- 한 파일에서 실패하더라도 나머지는 계속 처리하고, 마지막에 완료/실패 파일 및 오류 메시지를 보여줍니다. 안정성을 위해 **동시 추출하지 않고 순차 처리**합니다.

## 기존 개별 기능

- 파일 추가, 페이지 이동, 레이어 전체 켜기/끄기, 3분할 고정형 UI, 라이트/다크 테마를 유지합니다.
- **이미지 추출 기본값은 `원본 자동`**입니다. 지배적인 내장 래스터의 유효 픽셀 밀도 또는 순수 벡터 300 DPI를 기준으로 저장합니다.
- 필요한 경우에만 해상도를 `HD·FHD·QHD·4K`, `사용자 지정 가로·세로(최대 크기)`, `DPI 직접 지정(36~2400)`으로 변경할 수 있습니다.
- HD~4K와 사용자 지정 크기는 **도면의 원래 가로세로 비율을 보존**하는 최대 출력 영역입니다. 예를 들어 가로세로 비율이 2:1인 도면의 FHD 출력은 1920×960픽셀이며, 1920×1080으로 늘리거나 자르지 않습니다. 세로 도면에서는 가로세로 상한을 회전 적용합니다.
- 사용자 지정 크기·DPI 정책은 한 번 선택하면 현재 선택된 모든 파일의 **일괄 이미지 추출에 동일하게 적용**됩니다. 프로그램을 다시 켜면 기본 선택은 원본 자동입니다.
- 미리보기에서 휠 또는 +/−로 확대하면 원본의 **현재 보이는 영역만 고해상도로 갱신**합니다.

## 렌더링 최적화

- PDF OCG 내부 레이어가 고유하게 식별되는 경우 `set_layer_ui_config`를 활용하고 문서를 매번 직렬화하지 않습니다. OCG 구성이 복잡하면 안전한 호환 경로로 처리합니다.
- 미리보기는 화면 크기에 맞춰 빠르게 출력하며, **확대 시 전체 페이지를 고해상도로 재렌더링하지 않고 화면에 보이는 영역(clip)만 별도 렌더링합니다.** 현재 확대 위치를 유지한 채 레이어 갱신을 수행합니다.
- 레이어 연속 토글은 45ms 지연으로 합쳐 처리하고, 확대 이동 갱신은 105ms 지연으로 합쳐 처리합니다. 이미 오래된 결과는 화면에 게시하지 않습니다.
- 스레드별 동일 도면 재사용과 **최대 6개 / 18MB 미리보기 캐시**로 반복 확인 속도를 개선합니다. 동일한 레이어 상태·페이지·화면 크기의 재요청은 **이미지와 페이지 기하정보를 함께 캐시**해 중간 CAD/PDF 페이지 준비도 생략합니다. 일반 미리보기 PNG는 Pillow 재복사 대신 PyMuPDF 네이티브 PNG 인코딩을 사용합니다.
- DXF 흰색 선이 흰 배경에서 사라지지 않도록 CAD 색상 정책을 적용했습니다.

## 이미지 추출 — 용량 제한 제거·대용량 타일

- **5,000만 픽셀 제한을 제거했습니다.** 출력 크기를 자동 축소하지 않습니다.
- 원본에 지배적인 래스터 이미지가 있으면 해당 이미지의 실효 픽셀 밀도를 우선하며, **순수 벡터 PDF·DXF·DWG에는 고유 픽셀 해상도가 없어 자동 300 DPI로 렌더링**합니다.
- **12MP 이하**는 직접 렌더링으로 빠르게 저장합니다. **12MP 초과 PNG**는 메모리 예산(렌더 버퍼 약 12MB) 안에서 **전체 가로폭을 한 번에 그리는 세로 띠**를 우선 사용하고, 너무 넓은 도면에서만 가로 분할 타일로 자동 복귀합니다. PNG는 스트림으로 순차 기록하므로 전체 RGB 이미지를 메모리에 만들지 않습니다.
- **12MP 초과 JPG**도 같은 세로 띠 최적화 렌더를 임시 디스크 기반 RGB 버퍼로 모은 뒤 고품질 JPG(품질 98, 크로마 서브샘플링 없음)로 인코딩합니다. 최종 JPG 인코더의 주소 공간/메모리 요구량은 OS에 따라 달라질 수 있습니다.
- 파일 포맷·운영체제·저장 매체가 허용하는 실제 한도는 존재합니다. 이 프로그램은 **임의 4K/50MP 제한을 두지 않지만 물리적 메모리·저장 공간 제한까지 제거하는 것은 아닙니다.**
- PNG는 만들어진 픽셀을 무손실로 저장하지만, JPG는 손실 압축 형식입니다. 결과 JPG/PNG는 편집 가능한 PDF/CAD 레이어 구조를 보존하지 않습니다.
